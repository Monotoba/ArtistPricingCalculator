# Preliminary release dependency audit (2026-10-10)

## Evidence

- Source: GitHub Actions PR #12, run 38076863324, API 26 validation artifact `android-validation-reports-api-26`.
- Artifact file: `reports/dependencies/release-runtime.txt`, generated by Gradle `:app:dependencies --configuration releaseRuntimeClasspath`.
- Tested source revision: `0e167fd9427cd46e87d533f74555796df944ac98`.
- This is a **resolved dependency tree**, not a machine-readable license inventory or APK contents report.

## Inventory scope

The report includes 64 distinct Maven `group:artifact` coordinates matching the AndroidX, Google, and JetBrains groups inventoried. Major groups include:

- AndroidX: AppCompat, Activity, Fragment, Lifecycle, ConstraintLayout, RecyclerView, Material-adjacent support, Core, legacy support and more
- Google: `com.google.android.material:material`, Guava listenablefuture, Error Prone annotations
- JetBrains: Kotlin standard libraries and annotations, kotlinx.coroutines

The report may contain additional metadata/platform coordinates and does not prove which resources or classes are packaged in the final APK. Both direct and transitive dependencies need per-artifact notices and license verification against their corresponding published POMs/repositories.

## Checks still required before a public binary

1. Export exact resolved release artifacts and versions. Record authoritative license identifiers and links for **every** distributable component, including transitive dependencies; verify notices and obligations.
2. Differentiate runtime components bundled in the APK from compile-time metadata/platform entries.
3. Audit launcher and action icons included in the APK; verify ownership or replace any artwork whose provenance cannot be established.
4. Verify the provenance and redistributability of images in `docs/` that ship with the source repository.
5. Prepare and test a release-signed APK, verify SHA-256, check upgrade/data retention and physical-device compatibility; release signing must use a protected key, not a committed keystore.
6. Confirm support/distribution policy for minSdk 19 and targetSdk 26, separately from GitHub prerelease availability.

## Decision

**Incomplete / release-blocking.** No license is asserted merely from a project's brand or repository name. This document records evidence and outstanding review rather than claiming compliance.

Track open requirements in issues #11 (licenses/artwork) and #13 (physical-device tests).
